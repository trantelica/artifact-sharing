What Is It

A Portable Identity Layer for AI

A Personal Context Portfolio (PCP) is a structured set of ten markdown files that together form a machine-readable profile of you — your role, your relationships, your communication style, your goals, and your decision-making patterns.

📄

Plain Markdown Files

Human-readable, AI-readable, version-controllable. No proprietary format — they work everywhere.

🔌

Plugs Into Any Workflow

Drop them into a Claude Project, expose as an MCP resource, reference in a system prompt, or hand directly to an agent.

🌱

Living Documents

Projects change, priorities shift, relationships evolve. The PCP updates as you do — it's never finished, just current.

Use Cases — How It Stays Current

The PCP Is a Living System

Three built-in rhythms keep the PCP accurate over time — so your AI is always working from current information, not a snapshot from six months ago.

Daily
🌅

Daily Readiness Plan

Every morning, your AI pulls live data from your calendar, inbox, messages, and task list — then cross-references your PCP to produce a personalized briefing for the day ahead.

→ Who you're meeting and why it matters
→ Messages that need a response
→ Open tasks and decisions on your plate
→ Context on what's changed since yesterday
Event-Driven
💡

Session Debrief

After a significant meeting, decision, or project milestone, a debrief skill reviews what was learned and proposes targeted updates to the relevant PCP files. You approve before anything changes.

→ Paste in meeting notes or a transcript
→ Share a decision you just made
→ Drop in an email thread or a doc
→ PCP reflects the new reality
Periodic
🧹

PCP Audit

On a scheduled cadence, an audit skill scans every file for content that's gone stale — completed projects, changed relationships, outdated priorities. It produces a prioritized list of proposed edits for your review.

→ Prunes projects that are done
→ Flags priorities that have shifted
→ Surfaces inconsistencies across files
→ Nothing changes without your approval

The system improves with use — not because the AI gets smarter, but because the context it works from gets more accurate, specific, and current over time. A one-year-old PCP is significantly more powerful than a new one.

How to Build One

The interview-driven creation process — 30 to 60 minutes from zero to complete

Creation Process

Built Through a Structured Interview

A purpose-built interviewer agent walks you through all ten files one at a time — asking focused questions, drafting each file, and refining based on your feedback. You don't write anything from scratch.

1

Load the Interview Protocol

Paste the system prompt into Claude or your AI tool of choice. It becomes a focused interviewer — nothing else.

2

Work Through Each File

5–8 targeted questions per file. One question at a time. Interviewer pushes for specifics when you're vague.

3

Review and Refine Each Draft

The agent drafts each file and asks what's wrong. You correct it. It revises. Files sound like you, not like an AI describing you.

4

Download and Deploy

Ten markdown files ready to drop into any AI workflow — Claude Project, MCP resource, system prompt, or agent context.

Creation Process — Interview Design

How the Interview Agent Works

The protocol is designed to get specific, high-signal content — not generic summaries. A few key principles that make it work.

🎯

One Question at a Time

Never a list. Never compound. Single focused questions that let you think out loud without being overwhelmed.

🔍

Pushes for Specifics

When you give a vague answer, it follows up: "Can you give me an example of when that happened?" or "What does that look like on a Tuesday morning?"

🔗

Builds Across Files

Uses what it learned in File 2 to skip redundant questions in File 4. Collaborators you named in Projects show up in Relationships without re-asking.

"Here's my draft. Read through it and tell me what doesn't sound right — anything that feels off, anything I assumed wrong, anything that's missing. I'd rather revise now than have your agents working from bad context later."

— The interviewer agent's reaction pass prompt, delivered after every file
Maintenance

A PCP Gets Better Over Time

The initial build is the hardest part. After that, updates are incremental — triggered by natural session endings, not scheduled maintenance.

🔄

Post-Session Debrief

A debrief skill reviews what was learned in a session and proposes specific updates to the relevant files — you approve before anything changes.

🧹

Periodic Audits

A scheduled audit skill scans for staleness — projects that are done, relationships that have shifted, priorities that have changed — and surfaces a prioritized update list.

📬

Event-Driven Updates

Major changes — a new role, a reorg, a shift in strategy — prompt targeted file updates. Not a full rebuild, just the files that changed.

Files that need the most frequent updates:
↑↑

current-projects.md

↑

goals-and-priorities.md

Shifts with quarters and major decisions

↗

—

identity.md, communication-style.md

Stable — rarely needs changes

🗂️

Start With One File

You don't need all ten to begin. identity.md alone makes a meaningful difference. Build from there — the portfolio gets more valuable with every file you add.
